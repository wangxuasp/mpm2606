## 1. 概述

### 1.1 背景与目标

电科 45 所已在 Teamcenter 中构建产品设计数据（三维/二维模型、EBOM、设计变更），科研及批产型号数据均已纳入管理。面对产品转批产阶段，核心矛盾在于：**如何把设计数据转化为面向制造的数据，为采购、物料、生产制造提供准确有效的输入**。

`sol.md` 原方案基于 Teamcenter + NX CAD + MS Office 构建。本方案的目标是**自研一套轻量化、国产化、可独立部署的 Web 端工艺管理系统**，作为 Teamcenter 方案的并行/替代/前置验证形态，先以**纯前端单体应用**快速落地核心工艺业务能力，验证业务模型与交互范式，后续再按需对接 Teamcenter / ERP / MES。

### 1.2 核心价值（提炼自 sol.md 概述）

1. **应对指数级产品复杂度**：光刻机上万个零部件、装配层级十几层。将工艺从"电子纸笔"（Excel/PDF）升级为"工序-工步-操作-参数"结构化数据树，实现"物料-工具-工位-人员"的精准耦合。
2. **打通设计-制造数字孪生链路**：以 MBD 基于模型的工艺设计为理念，EBOM 变更可驱动 MBOM/装配规程联动更新，避免人工翻阅成百上千份工艺文档漏改错改。
3. **沉淀老师傅隐性知识**：通过典型工艺模板、标准工序库将经验数字化为"知识块"，新工程师可快速编制合规规程。
4. **为 AI+工业 提供燃料**：结构化数据是 AI 赋能前提，支撑工艺文件检查、历史文件自动结构化、辅助 BOM 转换等。

## 3. 核心业务模块设计

> 以下模块按 sol.md 第 3 章方案设计顺序提炼，标注【前端实现要点】说明无后端下的落地策略。

### 3.1 制造工艺规划器（主工作台）

**sol.md 要点**：用于 EBOM→MBOM 转换、同时创建编制工艺路线，支持多视图并排操作（左 EBOM、中 MBOM、右 工艺路线/三维）。

**前端实现要点**：
- 多面板可拖拽布局（`react-mosaic` 或 `allotment`），面板含：EBOM 树、MBOM 树、工艺路线树、工艺卡编辑器（OnlyOffice 嵌入）、三维图形窗口（JT 下载入口）、属性面板。
- 各 BOM/工艺路线树统一用 **AG Grid Tree Data** 渲染，跨面板拖拽：EBOM→MBOM 引用、MBOM→工序 消耗物料指派、资源库→工序 资源指派（AG Grid 行拖拽 + HTML5 Drag & Drop）。
- 工作上下文（当前协同关联、当前型号、当前用户）由 Zustand 全局管理。

### 3.2 设计工艺协同（EBOM-MBOM 关联）

**sol.md 要点**：
- EBOM/MBOM 根节点建立"协同关联"对象，无论从设计还是工艺侧都能互查，关联持久保存。
- 工艺路线节点按层级与 EBOM 零部件、MBOM 工艺虚拟件关联，方便数据传递与更改通知。
- 不影响已受控发布的 EBOM。

**前端实现要点**：
- "协同关联"建模为独立实体 `CollaborationLink { ebomRootId, mbomRootId, bopRootId, owner, createdAt }`，存 IndexedDB。
- 提供关联可视化视图（双树高亮对应节点）。
- 关联关系一旦建立不可自动断开（业务约束），UI 禁止随意删除。

### 3.3 MBOM 重构

**sol.md 要点**：
1. **目的**：将设计视角产物转化为制造视角，重构物理结构、补全制造信息（工艺虚拟件、辅料、包装）、支持下游、确保单一源头、驱动变更协同。
2. **工作内容**：结构重组与对齐（初始化、拆分合并、调整层级）→ 制造特性增补（非设计物料、物料属性：自制/外协/带料外协、消耗定额、报废率、工位代码）→ 责信度检查 → 工艺路径关联 → 审批发布。
3. **工艺虚拟件两类**：
   - 半成品虚拟件：需独立交付管理，图号含 "BC"，继承 EBOM 全部属性/模型/图纸/软件配置项。
   - 虚拟组：类似文件夹，本身不上 MBOM，子物料自动上 MBOM 根节点，支持嵌套。
4. **重构约束**：外购件及不带料外协下级不能出现自制件与带料外协。
5. **MBOM 属性**：批量编辑界面。
6. **MBOM 检查（责信度）**：源行无对应、源行多对应、目标行无源、数量差异等。
7. **审批/更改/查询**：多条件查询模板。

**前端实现要点**：
- MBOM 树用 **AG Grid Tree Data** 渲染（大规模虚拟滚动），支持拖拽引用、新建虚拟件/虚拟组、层级调整。
- 批量属性编辑器（AG Grid + 行内编辑 + 批量选择填充），列含：自制/外协/带料外协、物料消耗定额、报废率、工位分配代码、反冲领料、循环标识、固定损耗量/率、备件比例、子项类型等。
- **责信度检查**：前端 diff 算法比较 EBOM vs MBOM，输出四类结果（使用不足/过度使用/完全使用/部分匹配），支持从结果拖拽补分配。
- **约束校验**：Zod 业务规则，保存前校验外购件下级约束。
- 物料编码规则：半成品虚拟件图号含 "BC"、XN 等。

### 3.4 工艺路线（BOP）规划

**sol.md 要点**：
- **意义**：连接 EBOM/MBOM/BOP/车间的核心纽带，明确装配先后顺序、工位分配、接口关系；多团队并行规划；向 MES 下发作业计划、向 ERP 提供工时/资源/成本。
- **结构**：
  - 整机级"三层"：整机集成工艺—集成阶段—工序，每层独立版本/权限/单独审批/多人协同，关联 MBOM 节点。
  - 模块级"二层"：模块集成工艺—工序，不强制套在整机级下。
- **创建**：工艺编号 AS+7位流水码（AS0000001）；PERT 视图手工拖拽箭头形成"有向无环图 DAG"，输出到 APD。
- **协作及权限**：各层权限分配，整机负责人分配各集成阶段权限给专业工艺员；系统"信封"通知机制（收件箱/发件箱）。
- **审批/更改/查询**。

**前端实现要点**：
- 工艺路线树 + **React Flow PERT/DAG 编辑器**：节点拖拽、串/并行连线、DAG 校验（无环检测）、随路线节点增减自动重载。
- 协作"信封"系统：前端消息队列实体 `Inbox/Outbox`，按名称/发件人/时间过滤。
- 三层 vs 二层结构通过节点 `level` 与 `parentBopId` 表达。
- 版本管理：每层独立 `revision`，受控后只读。

### 3.5 工序编制

**sol.md 要点**：
1. **工序创建**：工序是工艺路线树叶子节点，不可嵌套；工序编号 OP+7位（OP0000001）。
2. **工序指派资源**：从 MBOM 拖拽主要/辅助物料绑定工序；从工艺资源库搜索拖拽设备/工装/工具；用"事例类型"区分主要消耗物料 vs 专用工装（MEConsumed/MEResource/METool）。
3. **工序内容编制**：工艺卡编辑器，1:1 还原企业工艺卡模板（附录4），与工艺路线双向关联、图文混编、单元格合并、导出 Excel；表头由系统自动填（MBOM 根图号、装配图图号、整机配置号）；系统名称/装配地点从字典库选择；环境要求条目化字典填写。
4. **工序行与工艺路线对应**：填工序名时选择工序，已关联填内容背景绿色，未关联红色。
5. **内嵌截图工具**：截图后编辑（文字/序号/箭头/图框/马赛克）、保存/复制粘贴到工艺卡，支持系统内外截图。
6. **检验工序编制**：是否自检/专检（是/否），新建"装配质量控制"模板页关联工序按行填写。
7. **专业组别**：机械/电气/光学/调试，批量编辑。
8. **工序检查**：责信度检查当前工序主要消耗物料是否分配完整（使用不足/过度使用/完全使用/部分匹配）。
9. **APD 导入**：方案一传统 Excel 模板导入；方案二智能化（见 Copilot）。

**前端实现要点**：
- **工艺卡编辑器**：**预留 OnlyOffice 组件接入接口**，由 OnlyOffice 文档服务器承载工艺卡（1:1 还原附录4 模板）的在线编辑，前端只负责上下文注入（表头 MBOM 根图号、装配图图号、整机配置号）、工序行关联状态高亮（绿/红）、合并单元格与批量序列化填表由 OnlyOffice 模板 + 脚本实现。前端封装 `OnlyOfficeEditor` 组件统一加载工艺卡/工艺文件，并预留 `onSave/onExport` 钩子回写结构化属性到本系统。**本期无 OnlyOffice 服务时，降级为只读预览 + 占位提示**，导出 Excel 仍由 `exceljs` 兜底。
- **截图工具**：浏览器 `getDisplayMedia` / `canvas` 截图 + 注释图层（箭头/马赛克/图框），结果转 blob 粘贴入工艺卡（OnlyOffice 嵌入态通过 API 插入）。
- **字典库**：系统名称、装配地点、环境要求条目作为前端字典数据（来自附件1/附件2）。
- **工序检查**：复用 3.3 责信度 diff 算法。

### 3.6 定额管理

**sol.md 要点**：
- **材料定额**：MBOM 预留属性批量编辑（编制部门、反冲领料、循环标识、固定损耗量/率、备件比例、子项类型等）；子项类型由系统在传 ERP 前计算，无法自动计算默认主材。
- **工时定额**：工序预留定额工时（数值，单位 H），批量编辑列与工艺卡工时单元格同属性。
- **人员定额**：工序预留定额人数，数值型批量编辑。

**前端实现要点**：定额列统一进入批量编辑器；材料定额"子项类型"由前端规则函数计算（默认主材）；批量编辑列与工艺卡单元格双向绑定同一 store 字段。

### 3.7 关键工序及关重件

**sol.md 要点**：
- **关键工序**：定义在工序属性（是/否，默认否）；关键工序出"关键工序质量控制"，非关键出"装配质量控制点"。
- **关重件标识**：定义在零部件属性，取值 空/G（关键件）/Z（重要件）；图纸受控发布时该属性锁定；TC 创建时填写、未送审/打回时编辑、工艺使用时继承；NX 图纸模板新增关重件栏位关联；存量数据批量维护工具。

**前端实现要点**：
- 工序"是否关键工序"开关，驱动工艺卡质量控制模板页类型。
- 零部件关重件属性三值下拉（空/G/Z），受控后只读锁定（前端状态机判定 `lifecycleState === 'released'`）。
- 存量批量维护工具（批量编辑器 + 临时性补录模式）。

### 3.8 工艺文件管理

**sol.md 要点**：
- **创建**：选中工艺/工序右键创建，选文件分类（调试说明、检验规范、检验记录表）、填名称备注、选本地 Office 文件；编号 WD+7位（WD0000001）；自动记录与工艺/工序关联。
- **编辑**：双击打开本地 Office 在线编辑，保存自动签入。
- **审批/更改/归集**：按产品自动归集到文件夹；更改不影响工艺路线版本，各自独立版本管理，往 MES 发最新发布版本。

**前端实现要点**：
- 工艺文件实体 `ProcessDocument { id(WD+7), category, name, remark, fileRef, linkedObjectId, version, lifecycleState }`。
- 工艺文件查看/编辑通过**预留 OnlyOffice 组件接入接口**实现（与工艺卡共用 `OnlyOfficeEditor` 封装），本期无 OnlyOffice 服务时降级为文件上传 + 只读预览占位，文件以 Blob 存 IndexedDB。
- 归集视图：按产品维度自动分组树（AG Grid Tree Data）。

### 3.9 工艺资源管理

**sol.md 要点**：
- **分类**：设备（通用可复用）/ 工具（通用或专用）/ 工装（产品专属，随产品定制）/ 辅料（不构成产品实体但不可或缺）。
- **库概念**：专人管理的"工艺资源库"文件夹，仅库管理员增删；入库手续从零部件引用到资源库；使用=工艺编制时从库搜索现行有效资源指派到工序。
- **入库**：途径1 工艺资源入库申请单（填条目→入库流程 申请-审核-入库，库管理员审核后系统自动放入对应位置）；途径2 管理员直接维护。
- **退库**：途径1 退库申请流程；途径2 管理员直接维护；退库仅从文件夹移除不删除，已被工艺路线使用的不受影响。
- **批量创建**：管理员整理 Excel 由系统管理员后台批量导入。
- **资源版本**：除专用工装外无版本概念恒 A 版，修改则换号；专用工装按自制件更改办法。
- **与集团主数据/ERP集成**：工具辅料设备走标准机械外购件申请；工装走机械零部件审批。

**前端实现要点**：
- 资源库树用 AG Grid Tree Data + 关键字模糊搜索；入库/退库申请单前端表单（AG Grid 明细行）+ 模拟审批流；分类目录按 `kind: equipment|tool|tooling|consumable`。
- 资源实体继承"零部件"类型字段（型号/名称/编号/状态/厂家/类别/使用状态）。
- 批量导入用 `exceljs` 解析 Excel 建库。
- 工装沿用"机械零部件"类型与更改流程。

### 3.10 工艺文件（APD）输出

**sol.md 要点**：基于工艺路线输出标准格式 APD，随 MBOM/工艺路线审批流程下发 MES；APD 版本跟随工艺路线版本，不单独授版本；Excel 版本附件关联到工艺阶段，支持单独或整本输出。

**前端实现要点**：APD 生成器读取结构化工艺路线 + MBOM + 工艺卡数据，用模板渲染为 Excel（`exceljs`，AG Grid 直接导出）+ PDF（打印或 OnlyOffice 转换）；版本号取自工艺路线 `revision`。

### 3.11 工艺审批

**sol.md 要点**：
- **MBOM及工艺路线审批**：审核 MBOM/工艺路线/APD 合法性，目标物 MBOM 根/工艺路线根/APD；编制节点完成时规则检查（外购件下级约束、APD 签署），不满足不能继续；审批环节 编制-审核-工艺-质量-批准。
- **MBOM及工艺路线投产流程**：必须受控 MBOM 和工艺路线版本才能进入；推送 ERP/MES。
- **工艺文件审批**：审核工艺文件合法性，目标物工艺文件版本，结束自动赋受控标识（无固定模板不自动签署封面）。
- **工作流模板**（表6）：MBOM和工艺路线审批流程、投产推送流程、工艺文件审批流程、工艺更改流程、工艺更改投产推送流程、工艺资源库入库流程、退库流程。

**前端实现要点**：
- 前端工作流引擎（XState）：定义上述 7 类流程模板，节点 编制→审核→工艺→质量→批准（入库流程 申请→审核→入库）。
- 编制节点规则检查为流程前置 guard，不通过阻断流转。
- 审批记录实体 `ApprovalRecord { targetId, targetType, template, currentNode, history[] }`，受控后赋 `lifecycleState='released'`。

### 3.12 工装设计管理

**sol.md 要点**：工装设计按现有工装编号创建机械零部件，NX 集成设计三维/工程图；审批用现有机械零部件审批流程；更改参考工装更改；入库=设计审批有效工装通过工艺资源入库流程纳入资源库；使用=工序中指派专用工装。

**前端实现要点**：工装作为"机械零部件"子类型纳入资源库；本期不做 NX 集成，三维模型以文件上传 + Viewer 查看替代；审批/更改/入库复用 3.9/3.11。

### 3.13 工艺技术状态（更改管理）

**sol.md 要点**：
- 由自制/工装设计人员发起"设计优化更改流程"或"图样更改审批流程"。
- 工艺更改两条并行主线：
  1. **主线1 工艺路线与 MBOM 更改**：创建工艺更改单→升版维护新版工艺路线（改工序/资源/主料/工时）→升版维护新版 MBOM（增减物料/改数量/改材料定额）→生成新版提交审批。
  2. **主线2 工艺文件更改**：升版填修改原因→编制新版本→提交审批。
- **创建工艺更改单向导 3 步**：①基本信息（更改单编号、产品代号、所属整机图号）；②更改内容+影响分析（系统比较当前版本 vs 旧版本，差异形成文字；更改原因分类：完善设计/设计改进/设计错误/总体要求/使用要求/协调要求/工艺要求/标准更新/描述错误；MBOM 比较增减物料种类与同种类数量变化，工艺路线比较增减工艺/工序节点、主要物料种类数量、设备工具差异）；③通知（手工追加+影响分析继承，审批通过后群发"信封"）。
- 工艺更改存储：更改单本体/更改前/更改后/关联设计更改单；受控随"工艺更改审核流程"，投产推送随"工艺更改投产审核流程"。
- **工艺文件更改**：选中已发布版本右键"修订"，填修改内容/影响分析，发"工艺文件更改流程"，MES 只传最新受控版本。
- **工装更改**：沿用机械零部件更改，使用该工装的工艺路线自动引用最新版。
- **工艺更改汇总**：条件组合查询（时间段/产品），自定义列，导出 Excel。

**前端实现要点**：
- 更改单向导组件（3 步 Stepper）；版本 diff 算法复用责信度比较，输出结构化差异 + 文字描述。
- 更改原因、影响分析为表单字段；通知人列表 + 信封群发。
- "修订"操作生成新 `revision`，旧版本保留只读；工艺路线引用工装始终解析最新受控版。
- 更改汇总：AG Grid + 多条件筛选 + `exceljs` 导出。

### 3.14 工艺汇总

**sol.md 要点**：从工艺路线提取汇总装入件/紧固件/设备工具/专用工装清单；提取材料定额/工时定额/人员定额清单。

**前端实现要点**：聚合查询引擎遍历工艺路线树 + 工序资源 + 定额字段，输出多张清单表，支持导出 Excel。

### 3.15 工艺三维可视化

**sol.md 要点**：
- **前置条件**：EBOM/MBOM/工艺路线每视图可关联"图形"窗口；设计师保存所有零部件 JT 模型，装配轻量化模型实时运算，保存装配关系保证三视图稳定。
- **按BOM查看**：重构过程中随时查看 EBOM/MBOM 轻量化模型。
- **按工序查看**：随工序一步步规划，整体装配模型逐步被还原；勾选每工序装入件，图形视图跟随变化。
- **爆炸图**：独立查看器，配置爆炸零部件、方向、间距，可保存配置；截图粘贴到工艺卡。
- **图形工具**：测量（任意位置标注测量值）、剖切（X/Y/Z 方向剖切装配体）、3D 零件移动（拖拽形成部分爆炸）、批注（零部件上锚定文字，空间变化仍关联）。

**前端实现要点**：
- **不在 Web 端实现 JT 解析/渲染**。三维查看器仅**预留 JT 模型下载接口**：按 BOM 节点 / 按工序提供"下载 JT 轻量化模型"按钮，调用统一的下载接口 `GET /api/3d/jt?nodeId=...&rev=...` 获取对应层级 JT 文件包（含装配关系 JT），交由本地查看器（如 NX Viewer / Teamcenter VisView / 桌面端）打开查看、做爆炸图/测量/剖切/移动/批注。
- Web 端保留：三维视图入口的上下文绑定（当前 BOM 节点/工序及装入件清单）、JT 文件清单展示、下载任务队列与状态。
- 爆炸图配置、测量/剖切/移动/批注等交互在本地查看器完成，结果截图可上传回工艺系统（文件 Blob）再粘贴入工艺卡。
- 后端接入后，下载接口可由 Teamcenter JT 数据集或预转换服务提供。

### 3.16 工艺 AI Copilot

**sol.md 要点**：采用"大模型+工艺知识+智能体"架构，5 场景：
1. 智能合规性审查
2. 智能 BOM 转换
3. 结构化智能编辑
4. **历史文档自动结构化导入**（重点详述）：人工提交 Excel APD → 后台文本提取、噪音过滤 → 文本切分、提取"实体-关系"、向量化 → 存图库 → 输出人能看懂的表格说明将建立哪些对象与层次关系 → 人工审核后批量创建。
5. 系统知识助手

**前端实现要点**：
- Copilot 侧边栏面板（命令面板式交互），本期全部 **Mock 响应 + 预留 `llm.invoke()` 接入点**。
- 历史文档结构化导入：前端解析 Excel（`exceljs`）→ 规则/正则初提取 + Mock LLM 实体识别 → 输出结构化对象预览表 → 人工勾选审核 → 批量写入 IndexedDB 建立工艺/工序/工具对象及关联。
- 向量库/图库本期用 Mock 占位，标注"后端待接入"。

## 9. 风险与约束

1. **无后端约束**：审批流、版本受控、并发协同均为前端模拟，多用户真实协同需后端补齐；本期定位为业务验证与演示。
2. **三维模型不在 Web 渲染**：sol.md 依赖 JT 轻量化模型，Web 端不做 JT 解析，仅预留 JT 下载接口；爆炸图/测量/剖切/批注由本地查看器完成。
3. **OnlyOffice 依赖**：工艺卡与工艺文件在线编辑依赖 OnlyOffice 文档服务器；本期未部署时降级为只读预览占位 + exceljs 兜底导出。
4. **AI 能力**：本期 Mock，真实智能审查/结构化导入需 LLM 服务与向量/图库后端。
5. **NX 集成缺失**：工装三维设计以文件上传替代。
6. **国产化部署**：Next.js 纯前端可静态导出部署，符合国产化环境网页访问要求；界面与数据全部简体中文，无国际化。
